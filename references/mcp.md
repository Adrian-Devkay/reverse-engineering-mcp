# Local MCP integration

The skill has an optional local stdio MCP server at `mcp_server.py`. It uses the official MCP Python SDK and LIEF, both installed into the skill's private virtual environment. The server is read-only: it hashes and parses files, extracts strings, and reads bounded byte ranges; it never executes a sample, makes network connections, or writes to an analyzed artifact.

For deep static analysis, the skill also connects to the local Ghidra MCP backend in `tools/ghidra-mcp`. It adds function recovery, decompilation, disassembly, call graphs, cross-references, namespace and symbol navigation, and byte-pattern search. Keep its project cache in a dedicated non-shared directory; project resets are disabled by default. The cache path intentionally avoids hidden path components rejected by Ghidra 12.

The optional free/open-source toolchain is catalogued in [toolchain.md](toolchain.md). Run `scripts/probe_toolchain.py` or the `apex_toolchain_inventory` MCP tool before relying on a backend. The inventory reports availability, integration state, and isolation requirements without exposing executable paths. Dynamic, emulation, fuzzing, and host-forensics tools remain approval- and isolation-gated. A missing executable or module must be reported as unavailable, not silently substituted.

Use `scripts/capability_report.py` after preflight to record readiness against the capability contracts. A target score of 9 requires the evidence contract and the relevant backend/isolation checks; a detected executable alone is never a score of 9.

The Codex configuration must launch the server with an absolute interpreter path and an explicit `APEX_MCP_ALLOWED_ROOTS` allowlist. Add only a dedicated case directory that contains authorized samples. There is no safe default root; do not use a shared `/tmp` directory unless the user has explicitly created and isolated a case directory there. MCP output redacts absolute paths by default; set `APEX_MCP_REVEAL_PATHS=1` only for a local case where full paths are required.

Use the bundled MCP for deterministic triage. `apex_static_tool` can invoke only its fixed, bounded, read-only adapter set (`file`, `readelf`, `objdump`, `nm`, `strings`, `llvm-readobj`, and `llvm-objdump`). Use a separately configured Ghidra, Rizin, debugger, emulator, fuzzer, or forensic backend only when the inventory and isolation contract support it. The stack still does not replace a debugger or a sandbox.

If a file is outside the allowlist, expand the allowlist only after confirming scope. The server rejects requests when the allowlist is absent, caps binary/YARA/static-tool input sizes, and does not expose local tool paths by default. Static adapters use no shell, fixed arguments, bounded output, a process timeout, and POSIX child resource limits when supported; still use an external sandbox for hostile or malformed files. Do not weaken the read-only design to add execution, live debugging, firmware flashing, external network access, or arbitrary shell commands without a separate review and explicit authorization.
